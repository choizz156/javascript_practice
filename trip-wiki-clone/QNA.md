# Trip Wiki Clone - Q&A 기록

이 문서는 Trip Wiki Clone 프로젝트를 진행하면서 주고받은 주요 질문과 답변을 정리한 기록입니다.

## 1. 왜 Vite를 쓰나요?
**Q: 옛날처럼 그냥 HTML 파일을 브라우저에서 열면 안 되나요? 왜 굳이 Vite를 쓰나요?**
**A:** 
1. **ES Modules (`import/export`) 지원:** 모듈화를 위해 파일을 쪼개면 브라우저 보안 정책(CORS) 때문에 그냥 HTML을 열어서는 동작하지 않습니다. Vite가 제공하는 로컬 개발 서버를 띄워야만 정상적으로 작동합니다.
2. **HMR (Hot Module Replacement):** 코드를 수정하고 저장(Ctrl+S)하면 브라우저 전체를 새로고침할 필요 없이 수정한 부분만 0.1초 만에 마법처럼 즉시 갱신됩니다. 개발 속도가 엄청나게 빨라집니다.
3. **미래 지향적 (Vue 3 공식 도구):** Vue 3의 창시자가 만든 도구이며, 현재 모든 Vue 3 프로젝트의 표준입니다. 바닐라 JS에서 Vite에 익숙해지면 나중에 Vue 3로 넘어갈 때 매우 수월합니다.

## 2. npm과 npx의 차이
**Q: npm install 할 때 npm은 알겠는데, 프로젝트 만들 때 쓴 npx는 뭔가요?**
**A:** 
- **`npm` (Node Package Manager):** 마치 철물점에서 공구를 "구매"해서 내 컴퓨터(node_modules)에 영구적으로 보관하고 계속 사용하는 것입니다.
- **`npx` (Node Package Execute):** 거대한 공구를 굳이 사지 않고, 딱 한 번만 "렌탈(대여)"해서 작업(예: 프로젝트 뼈대 생성)을 마친 뒤 바로 반납하여 용량을 차지하지 않게 하는 마법의 1회용 실행 명령어입니다.

## 3. 기본 파일들을 싹 지우는 이유
**Q: 처음 Vite 프로젝트를 만들고 나서 왜 counter.js, javascript.svg 등을 다 지우고 시작하나요?**
**A:** 
우리는 완전한 백지상태에서 우리만의 '여행지 위키'를 만들 것이기 때문입니다. Vite가 초보자를 위해 넣어둔 카운터 버튼 예제나 로고 이미지 등은 우리 프로젝트에 불필요한 "쓰레기 코드"이므로 충돌을 막기 위해 싹 청소하는 것입니다. (`main.js`를 `index.js`로 바꾼 것은 원본 프로젝트와 구조를 똑같이 맞추기 위함입니다.)

## 4. 클래스(this) 방식에서 `new` 키워드의 중요성
**Q: 예전 연습에서는 함수를 그냥 호출했는데, 여기서는 왜 `new App()` 처럼 new를 붙이나요?**
**A:** 
원본 코드가 객체 지향(`this` 활용) 방식으로 작성되었기 때문입니다. 함수를 그냥 호출하면 `this`가 브라우저 전체(`window`)를 가리켜 심각한 버그가 발생합니다. `new`를 붙이면 "새로운 붕어빵(빈 객체)"이 구워지고 `this`가 그 붕어빵을 가리키게 되어, 내 상태(`this.state`)를 안전하게 보관할 수 있습니다. 
*(참고: 이후 우리는 최신 트렌드인 '클로저(Closure)' 방식으로 우회하여 `new`와 `this` 없이 더욱 안전하고 깔끔하게 구현하는 방향으로 노선을 변경했습니다!)*

## 5. Vite 자동 새로고침(HMR) 작동 조건
**Q: Vite 쓰면 새로고침 안 해도 된다고 했는데, 화면이 안 바뀝니다. 어떻게 설정하나요?**
**A:** 
기본적으로 내장된 기능이므로 별도 설정은 필요 없습니다. 안 된다면 아래 3가지를 체크해야 합니다.
1. 터미널에 `npm run dev` 서버가 켜져 있는지 확인
2. 브라우저 주소창이 로컬 서버 주소(`http://localhost:5173/`)인지 확인 (절대 `file:///...` 형태가 아님)
3. 코드 편집기(VS Code)에서 실제로 파일을 저장(Ctrl+S)했는지 확인

## 6. 구조 분해 할당(Destructuring)의 실무 적용
**Q: App.js 렌더링 함수에 구조 분해 할당을 쓰는 건 어떻게 생각하나요?**
**A:** 
**매우 적극 권장하며 실무의 표준 방식입니다.** 
매번 `state.currentPage`, `state.cities` 처럼 `state.` 꼬리표를 달아주는 대신, `const { currentPage, cities } = state;`로 미리 꺼내두면 코드가 훨씬 간결해지고 가독성이 뛰어납니다. 데이터가 많아질수록 그 진가를 발휘합니다.

## 7. `Cannot read properties of undefined` 에러와 방어 코드 (단축 평가)
**Q: 데이터를 불러올 때 `const citiesArray = state && state.cities ? state.cities : [];` 같은 코드를 왜 써야 하나요? 그냥 쓰면 안 되나요?**
**A:** 
데이터 통신에는 **'시간차(로딩)'**가 존재하기 때문입니다. 화면을 처음 그리는 0.00초에는 아직 서버에서 데이터가 오지 않아 `state.cities`가 비어있습니다(undefined). 이때 강제로 값을 꺼내려 하면 자바스크립트는 에러를 뱉고 앱을 다운시킵니다. 따라서 **"데이터가 아직 안 왔으면 일단 빈 배열(\`[]\`)로 에러를 막고 뼈대만 그려!"**라는 안전망(방패) 역할을 하는 필수 방어 코드입니다.

## 8. 데이터가 도착하면 알아서 다시 화면이 그려지나요?
**Q: 데이터가 오면 화면이 다시 렌더링(Re-render)되는 건가요?**
**A:** 
일반적인 React/Vue에서는 '상태(State)'가 변하면 자동으로 화면이 다시 그려집니다. 하지만 우리가 현재 바닐라 JS로 짠 `App.js` 구조에서는 **데이터를 기다렸다가(\`await\`), 통신이 완전히 끝나고 데이터가 준비된 후에 수동으로 \`render()\` 함수를 딱 1번만 호출**하도록 설계되어 있습니다. (이 때문에 로딩 중 에러가 아닌 구조 분해 할당 문법 에러가 발생했던 것입니다.)

## 9. HTML을 일일이 다 수기로 적어야 하나요?
**Q: 바닐라 JS로 하니까 백틱 안에 HTML을 다 적어야 하는데 원래 이런 건가요?**
**A:** 
네, 순수 바닐라 JS에서는 템플릿 리터럴(백틱) 안에 HTML 문자열을 넣어서 화면을 그리는 것이 최선입니다. 이 과정이 너무 번거롭고 귀찮기 때문에 실무에서는 HTML 작성을 훨씬 편하게 해주는 **Vue.js(\`<template>\`)**나 **React(JSX)** 같은 프레임워크를 사용하게 되는 것입니다. 이번 프로젝트에서는 복사/붙여넣기를 적극 활용하시면서 데이터의 흐름 위주로만 파악하셔도 충분합니다!

## 10. 완벽한 로직(`region || "ALL"`)이 실패한 이유
**Q: 값을 안전하게 넣기 위해 `region || "ALL"` 이라고 적었는데 왜 에러가 났을까요? 제 코드가 틀린 건가요?**
**A:** 
아닙니다! 자바스크립트 문법과 논리(단축 평가) 측면에서는 100점짜리 완벽한 코드였습니다. 하지만 앱 개발에서는 내 코드만 잘 짜는 것이 끝이 아니라, **"외부 서버(API)가 어떤 형태의 데이터를 원하는가(API 스펙)"**를 파악하는 것이 똑같이 중요합니다. 해당 서버는 전체 데이터를 원할 때 `"ALL"`이라는 글자 대신 **"아무 글자도 없는 빈 문자열(`""`)"**을 요구하도록 설계되어 있었기 때문에 서로 말이 통하지 않았을 뿐입니다.

## 11. 다른 탭을 눌렀을 때 빈 화면이 나오는 이유 (서버의 숨겨진 규칙)
**Q: 'Asia' 탭을 눌렀을 때 에러는 안 나는데 사진이 아예 안 나오는 이유는 무엇인가요?**
**A:** 
이 역시 API 서버가 숨겨놓은 까다로운 규칙 때문입니다. 전체 목록을 부를 때와 달리, 특정 지역(Asia)을 부를 때는 **"무조건 주소 맨 끝에 `?start=0` (0번째 사진부터 줘!)이라는 꼬리표를 붙여야만"** 데이터를 내려주도록 서버가 코딩되어 있었습니다. 이 꼬리표가 없으니 서버가 에러 대신 아예 빈 데이터(`[]`)를 주었고, 결과적으로 화면에 아무것도 그려지지 않은 것입니다.

## 12. 조건문 안의 `!currentPage.includes("/city/")` 의 의미
**Q: `includes("/city/")` 이건 무슨 뜻인가요?**
**A:** 
`includes()`는 자바스크립트가 기본 제공하는 "단어 검색기"입니다. 문장 안에 특정 단어가 있으면 `true`를 반환합니다. 
앞에 `!`(NOT)가 붙었으므로, **"현재 브라우저 주소(`currentPage`)에 `/city/`라는 단어가 포함되어 있지 않을 때만"** 이라는 뜻이 됩니다. 메인 화면에서는 검색창과 정렬 버튼을 보여주고, 특정 도시 딱 하나만 보여주는 상세 페이지(`/city/12`)로 들어갔을 때는 굳이 필요 없는 검색창/정렬 버튼을 깔끔하게 숨기기 위해 사용한 똑똑한 가림막입니다.

## 13. `innerHTML +=` 의 치명적인 함정과 `insertAdjacentHTML`
**Q: 헤더에 이벤트를 잘 달았는데 왜 정렬/검색이 작동하지 않았나요?**
**A:** 
초보자들이 가장 많이 겪는 바닐라 JS의 함정입니다! 화면을 그릴 때 썼던 `$app.innerHTML +=` 명령어는 단순히 내용을 추가하는 것이 아니라, **"기존에 지어둔 레고 집을 망치로 싹 다 부수고 텍스트로 된 도면을 바탕으로 처음부터 다시 조립하는"** 파괴적인 명령어입니다. 집이 부서지면서 헤더에 예쁘게 달아두었던 '센서(이벤트 리스너)'도 함께 쓰레기통에 버려졌던 것이죠. 
## 14. 일부 단어만 검색해도 찾아지는 원리 (프론트엔드와 백엔드의 협력)
**Q: 검색창에 'to' 같은 일부 단어만 쳐도 어떻게 검색이 되는 건가요? 이 복잡한 기능도 제가 만든 건가요?**
**A:** 
해당 기능 자체는 API 서버(백엔드)가 처리하고 있습니다! 서버 내부적으로 "대소문자를 무시하고 도시 이름(City)과 국가 이름(Country) 중 어디든 해당 단어가 포함되어 있으면 모두 반환(부분 일치 검색)" 하도록 미리 코딩되어 있습니다. 
사용자님은 사용자의 입력을 받아 서버로 주문(`&search=to`)을 넣는 완벽한 **프론트엔드**를 만드신 것이고, 복잡한 데이터 검색은 **백엔드**가 처리하는 전형적인 클라이언트-서버 협력 모델의 결과물입니다.

## 15. 탭 전환 시 화면이 심하게 깜박거리는 현상 (이벤트 리스너 메모리 누수)
**Q: 탭을 누를 때마다 화면이 이전 사진들과 겹치면서 렉 걸린 것처럼 엄청나게 깜박거립니다.**
**A:** 
정말 무서운 **'좀비 센서(메모리 누수)'** 버그였습니다! 기존 `RegionList.js`에서 탭 클릭 센서(`addEventListener`)를 최상위 요소인 `$app`에 전역으로 달아두었는데, 탭을 눌러 컴포넌트 함수가 다시 실행(렌더링)될 때마다 이 센서가 무한 복제(1개 ➔ 2개 ➔ 4개...)되고 있었습니다. 그 결과 한 번만 클릭해도 서버 요청과 화면 그리기가 수차례 동시 다발적으로 폭주한 것입니다.
이를 해결하기 위해, `$app` 대신 **새로 그려지는 특정 네비게이션 영역(`regionNav`)에만 센서를 달도록** 수정했습니다. 이렇게 하면 화면이 다시 그려질 때 예전 영역과 함께 예전 센서도 깔끔하게 쓰레기통에 버려져서 중복 실행을 막을 수 있습니다.
