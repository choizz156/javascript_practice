# Trip Wiki Clone - Q&A 기록

이 문서는 Trip Wiki Clone 프로젝트를 진행하면서 주고받은 주요 질문과 답변을 정리한 기록입니다.

## 1. 왜 Vite를 쓰나요?
**Q: 옛날처럼 그냥 HTML 파일을 브라우저에서 열면 안 되나요? 왜 굳이 Vite를 쓰나요?**
**A:** 
1. **ES Modules (`import/export`) 지원:** 모듈화를 위해 파일을 쪼개면 브라우저 보안 정책(CORS) 때문에 그냥 HTML을 열어서는 동작하지 않습니다. Vite가 제공하는 로컬 개발 서버를 띄워야만 정상적으로 작동합니다.
2. **HMR (Hot Module Replacement):** 코드를 수정하고 저장(Ctrl+S)하면 브라우저 전체를 새로고침할 필요 없이 수정한 부분만 0.1초 만에 마법처럼 즉시 갱신됩니다. 개발 속도가 엄청나게 빨라집니다.
3. **미래 지향적 (Vue 3 공식 도구):** Vue 3의 창시자가 만든 도구이며, 현재 모든 Vue 3 프로젝트의 표준입니다. 바닐라 JS에서 Vite에 익숙해지면 나중에 Vue 3로 넘어갈 때 매우 수월합니다.

## 2. npm과 npx의 차이
**Q: npm install 할 때 npm은 알겠는데, 프로젝트 만들 때 쓴 npx는 뭔가요?**
**A:** 
- **`npm` (Node Package Manager):** 마치 철물점에서 공구를 "구매"해서 내 컴퓨터(node_modules)에 영구적으로 보관하고 계속 사용하는 것입니다.
- **`npx` (Node Package Execute):** 거대한 공구를 굳이 사지 않고, 딱 한 번만 "렌탈(대여)"해서 작업(예: 프로젝트 뼈대 생성)을 마친 뒤 바로 반납하여 용량을 차지하지 않게 하는 마법의 1회용 실행 명령어입니다.

## 3. 기본 파일들을 싹 지우는 이유
**Q: 처음 Vite 프로젝트를 만들고 나서 왜 counter.js, javascript.svg 등을 다 지우고 시작하나요?**
**A:** 
우리는 완전한 백지상태에서 우리만의 '여행지 위키'를 만들 것이기 때문입니다. Vite가 초보자를 위해 넣어둔 카운터 버튼 예제나 로고 이미지 등은 우리 프로젝트에 불필요한 "쓰레기 코드"이므로 충돌을 막기 위해 싹 청소하는 것입니다. (`main.js`를 `index.js`로 바꾼 것은 원본 프로젝트와 구조를 똑같이 맞추기 위함입니다.)

## 4. 클래스(this) 방식에서 `new` 키워드의 중요성
**Q: 예전 연습에서는 함수를 그냥 호출했는데, 여기서는 왜 `new App()` 처럼 new를 붙이나요?**
**A:** 
원본 코드가 객체 지향(`this` 활용) 방식으로 작성되었기 때문입니다. 함수를 그냥 호출하면 `this`가 브라우저 전체(`window`)를 가리켜 심각한 버그가 발생합니다. `new`를 붙이면 "새로운 붕어빵(빈 객체)"이 구워지고 `this`가 그 붕어빵을 가리키게 되어, 내 상태(`this.state`)를 안전하게 보관할 수 있습니다. 
*(참고: 이후 우리는 최신 트렌드인 '클로저(Closure)' 방식으로 우회하여 `new`와 `this` 없이 더욱 안전하고 깔끔하게 구현하는 방향으로 노선을 변경했습니다!)*

## 5. Vite 자동 새로고침(HMR) 작동 조건
**Q: Vite 쓰면 새로고침 안 해도 된다고 했는데, 화면이 안 바뀝니다. 어떻게 설정하나요?**
**A:** 
기본적으로 내장된 기능이므로 별도 설정은 필요 없습니다. 안 된다면 아래 3가지를 체크해야 합니다.
1. 터미널에 `npm run dev` 서버가 켜져 있는지 확인
2. 브라우저 주소창이 로컬 서버 주소(`http://localhost:5173/`)인지 확인 (절대 `file:///...` 형태가 아님)
3. 코드 편집기(VS Code)에서 실제로 파일을 저장(Ctrl+S)했는지 확인

## 6. 구조 분해 할당(Destructuring)의 실무 적용
**Q: App.js 렌더링 함수에 구조 분해 할당을 쓰는 건 어떻게 생각하나요?**
**A:** 
**매우 적극 권장하며 실무의 표준 방식입니다.** 
매번 `state.currentPage`, `state.cities` 처럼 `state.` 꼬리표를 달아주는 대신, `const { currentPage, cities } = state;`로 미리 꺼내두면 코드가 훨씬 간결해지고 가독성이 뛰어납니다. 데이터가 많아질수록 그 진가를 발휘합니다.
