# Trip Wiki Clone - Q&A 기록

이 문서는 Trip Wiki Clone 프로젝트를 진행하면서 주고받은 주요 질문과 답변을 정리한 기록입니다.

## 1. 왜 Vite를 쓰나요?
**Q: 옛날처럼 그냥 HTML 파일을 브라우저에서 열면 안 되나요? 왜 굳이 Vite를 쓰나요?**
**A:** 
1. **ES Modules (`import/export`) 지원:** 모듈화를 위해 파일을 쪼개면 브라우저 보안 정책(CORS) 때문에 단순히 HTML 파일을 로컬에서 열어서는 동작하지 않습니다. Vite가 제공하는 로컬 개발 서버를 띄워야만 정상적으로 작동합니다.
2. **HMR (Hot Module Replacement):** 코드를 수정하고 저장하면 브라우저 전체를 새로고침할 필요 없이 수정한 모듈만 즉시 갱신됩니다. 이를 통해 개발 생산성이 크게 향상됩니다.
3. **미래 지향적 (Vue 3 공식 도구):** Vue 3의 창시자가 만든 빌드 도구이며, 현재 생태계의 표준으로 자리 잡고 있습니다. 바닐라 JS 단계에서 Vite 환경에 익숙해지면 향후 프레임워크 도입 시 매우 수월합니다.

## 2. npm과 npx의 차이
**Q: npm install 할 때 npm은 알겠는데, 프로젝트 만들 때 쓴 npx는 뭔가요?**
**A:** 
- **`npm` (Node Package Manager):** 패키지를 내 컴퓨터(node_modules)에 영구적으로 설치하고 계속 사용하는 명령어입니다.
- **`npx` (Node Package Execute):** 패키지를 로컬에 설치하지 않고, 원격 저장소에서 일회성으로 다운로드하여 실행한 뒤 즉시 삭제하는 명령어입니다. 프로젝트 스캐폴딩(초기 설정) 시 로컬 용량을 차지하지 않아 유용합니다.

## 3. 기본 파일들을 싹 지우는 이유
**Q: 처음 Vite 프로젝트를 만들고 나서 왜 counter.js, javascript.svg 등을 다 지우고 시작하나요?**
**A:** 
초기화된 백지상태에서 아키텍처를 직접 구성하기 위함입니다. Vite가 기본 제공하는 카운터 예제나 로고 이미지 등은 현재 프로젝트에 불필요한 보일러플레이트 코드이므로 충돌을 막기 위해 제거합니다.

## 4. 클래스(this) 방식에서 `new` 키워드의 중요성
**Q: 예전 연습에서는 함수를 그냥 호출했는데, 여기서는 왜 `new App()` 처럼 new를 붙이나요?**
**A:** 
원본 코드가 객체 지향(`this` 활용) 방식으로 작성되었기 때문입니다. 생성자 함수를 그냥 호출하면 `this`가 전역 객체(`window`)를 바인딩하여 심각한 버그가 발생합니다. `new` 키워드를 붙여 인스턴스를 생성해야 `this`가 해당 인스턴스를 가리키게 되어, 컴포넌트의 상태(`this.state`)를 안전하게 캡슐화할 수 있습니다. 
*(참고: 이후 프로젝트 진행 과정에서 클로저(Closure) 패턴을 활용하여 `new`와 `this` 없이 더욱 안전하고 선언적인 함수형 컴포넌트 방식으로 리팩토링을 진행했습니다.)*

## 5. Vite 자동 새로고침(HMR) 작동 조건
**Q: Vite 쓰면 새로고침 안 해도 된다고 했는데, 화면이 안 바뀝니다. 어떻게 설정하나요?**
**A:** 
기본적으로 내장된 기능이므로 별도 설정은 필요 없습니다. 작동하지 않는다면 아래 3가지를 체크해야 합니다.
1. 터미널에 `npm run dev` 스크립트를 통해 개발 서버가 실행 중인지 확인
2. 브라우저 주소창이 로컬 서버 주소(`http://localhost:5173/`)인지 확인
3. 코드 에디터(VS Code)에서 파일 저장이 정상적으로 완료되었는지 확인

## 6. 구조 분해 할당(Destructuring)의 실무 적용
**Q: App.js 렌더링 함수에 구조 분해 할당을 쓰는 건 어떻게 생각하나요?**
**A:** 
**매우 적극 권장하며 실무의 표준 패턴입니다.** 
매번 `state.currentPage`, `state.cities` 처럼 객체 접근자를 사용하는 대신, `const { currentPage, cities } = state;` 형태로 미리 할당해두면 코드가 훨씬 간결해지고 가독성이 뛰어납니다. 데이터 뎁스가 깊어질수록 그 진가를 발휘합니다.

## 7. `Cannot read properties of undefined` 에러와 방어 코드 (단축 평가)
**Q: 데이터를 불러올 때 `const citiesArray = state && state.cities ? state.cities : [];` 같은 코드를 왜 써야 하나요? 그냥 쓰면 안 되나요?**
**A:** 
비동기 데이터 통신에는 **네트워크 지연(Latency)**이 존재하기 때문입니다. 화면을 최초 렌더링하는 시점에는 아직 서버 응답이 도착하지 않아 `state.cities`가 `undefined` 상태일 수 있습니다. 이때 객체 프로퍼티에 강제로 접근하려 하면 런타임 에러가 발생합니다. 따라서 데이터가 할당되기 전까지는 빈 배열(`[]`)을 기본값으로 반환하게 하여 렌더링 에러를 방지하는 방어 로직(단축 평가)입니다.

## 8. 데이터가 도착하면 알아서 다시 화면이 그려지나요?
**Q: 데이터가 오면 화면이 다시 렌더링(Re-render)되는 건가요?**
**A:** 
일반적인 React/Vue와 같은 프레임워크에서는 상태(State) 변경을 감지하여 자동으로 리렌더링을 수행합니다. 하지만 현재 바닐라 JS 기반 구조에서는 비동기 통신(`await fetch()`)이 완전히 종료되고 데이터가 상태 객체에 할당된 직후에 수동으로 `render()` 함수를 호출하도록 명시적으로 설계되어 있습니다.

## 9. HTML을 일일이 다 수기로 적어야 하나요?
**Q: 바닐라 JS로 하니까 백틱 안에 HTML을 다 적어야 하는데 원래 이런 건가요?**
**A:** 
네, 순수 바닐라 JS에서는 템플릿 리터럴(백틱)을 활용하여 문자열 형태로 DOM을 생성하고 주입하는 방식이 일반적입니다. 이러한 템플릿 작성의 번거로움과 유지보수의 어려움을 해결하기 위해 실무에서는 **Vue.js(\`<template>\`)**나 **React(JSX)** 같은 프레임워크를 도입하게 됩니다.

## 10. API 스펙의 중요성 (`region || "ALL"`)
**Q: 값을 안전하게 넣기 위해 `region || "ALL"` 이라고 적었는데 왜 에러가 났을까요? 제 코드가 틀린 건가요?**
**A:** 
자바스크립트 문법(단축 평가) 측면에서는 완벽한 코드였습니다. 하지만 클라이언트 코드의 무결성만큼이나 **API 서버의 명세(Specification)**를 정확히 파악하는 것이 중요합니다. 해당 백엔드 API는 전체 데이터를 요청할 때 `"ALL"`이라는 문자열 대신 빈 문자열(`""`)을 파라미터로 요구하도록 설계되어 있었기 때문에 발생하는 스펙 불일치 이슈였습니다.

## 11. 쿼리스트링 파라미터 규칙 (서버 스펙)
**Q: 'Asia' 탭을 눌렀을 때 에러는 안 나는데 사진이 아예 안 나오는 이유는 무엇인가요?**
**A:** 
이 역시 백엔드 API의 설계 스펙에 기인합니다. 전체 목록 요청과 달리, 특정 지역 파라미터(Asia)를 전달할 때는 페이징 처리를 위해 무조건 **`?start=0` 쿼리스트링을 필수 값으로 포함**하도록 서버 로직이 작성되어 있었습니다. 필수 파라미터가 누락되어 서버가 빈 배열(`[]`)을 반환한 것입니다.

## 12. 조건문 안의 `!currentPage.includes("/city/")` 의 의미
**Q: `includes("/city/")` 이건 무슨 뜻인가요?**
**A:** 
`includes()`는 문자열 내에 특정 문자열이 포함되어 있는지 여부를 불리언(`true`/`false`)으로 반환하는 String 메서드입니다. 
앞에 논리 부정 연산자(`!`)가 결합되어, **"현재 URL(`currentPage`) 경로에 `/city/` 라우팅이 포함되지 않았을 경우"**를 의미합니다. 즉, 상세 페이지 라우트가 아닐 때만 메인 화면용 UI(검색창, 정렬 버튼 등)를 조건부 렌더링하기 위한 로직입니다.

## 13. `innerHTML +=` 의 렌더링 이슈와 `insertAdjacentHTML`
**Q: 헤더에 이벤트 리스너를 잘 연결했는데 왜 정렬/검색이 작동하지 않았나요?**
**A:** 
바닐라 JS 렌더링 시 흔히 발생하는 DOM 파괴 이슈입니다. `$app.innerHTML +=`를 사용하면 기존 DOM 요소를 완전히 덮어쓰면서(초기화 후 재파싱) 새롭게 DOM 노드를 생성합니다. 이 과정에서 기존 노드에 바인딩되어 있던 모든 이벤트 리스너가 메모리에서 유실됩니다. 이를 해결하기 위해 기존 DOM 트리를 보존하면서 새로운 노드만 특정 위치에 삽입하는 **`$app.insertAdjacentHTML("beforeend", ...)`** 메서드로 리팩토링하여 이벤트 바인딩을 유지했습니다.

## 14. 백엔드 부분 일치 검색 기능
**Q: 검색창에 'to' 같은 일부 단어만 쳐도 어떻게 검색이 되는 건가요? 이 복잡한 기능도 제가 만든 건가요?**
**A:** 
검색 쿼리 프로세싱은 전적으로 API 서버(백엔드)가 담당하고 있습니다. 백엔드 컨트롤러 내부에서 쿼리스트링으로 전달받은 키워드를 바탕으로 데이터베이스의 다중 컬럼(City, Country)에 대해 대소문자를 구분하지 않는 부분 일치(LIKE 조건 등) 검색을 수행하도록 구현되어 있습니다. 프론트엔드는 사용자의 입력값을 캡처하여 정확한 쿼리 파라미터(`&search=to`)로 변환 및 전송하는 훌륭한 클라이언트 역할을 수행한 것입니다.

## 15. 컴포넌트 재렌더링 시 이벤트 리스너 메모리 누수
**Q: 탭을 누를 때마다 화면이 이전 사진들과 겹치면서 렉 걸린 것처럼 엄청나게 깜박거립니다.**
**A:** 
이벤트 리스너의 **다중 바인딩 및 메모리 누수(Memory Leak)** 버그였습니다. `RegionList.js`에서 탭 클릭 이벤트 리스너를 최상위 전역 요소인 `$app`에 직접 바인딩했는데, 컴포넌트 함수가 재호출(리렌더링)될 때마다 동일한 리스너가 누적해서 중복 등록(1개 ➔ 2개 ➔ 4개...)되고 있었습니다. 그 결과 한 번의 클릭에 수많은 네트워크 요청과 렌더링 사이클이 동시다발적으로 발생했습니다.
이를 해결하기 위해 최상위 요소가 아닌, **렌더링 시마다 새롭게 생성되는 하위 노드(`regionNav`)에만 이벤트를 위임(Event Delegation)**하도록 수정했습니다. 이로써 재렌더링 시 이전 DOM 노드와 함께 바인딩된 리스너가 자연스럽게 가비지 컬렉션(GC)되어 중복 실행을 원천 차단했습니다.

## 16. 구조 분해 할당(Destructuring)의 선택적 활용
**Q: `const { cities } = state` 처럼 굳이 구조 분해 할당을 안 쓰고 직접 `state.cities`로 넘기면 안 되나요?**
**A:** 
물론입니다! 구조 분해 할당은 객체 접근을 간결하게 만들어주는 **문법적 설탕(Syntactic Sugar)**일 뿐 필수가 아닙니다. 오히려 구조 분해로 추출한 변수는 원본 객체 프로퍼티의 복사본(값 또는 참조)이므로, 추출된 변수에 직접 재할당을 시도하다가 원본 상태를 업데이트하지 못하는 사이드 이펙트를 유발할 수 있습니다. 혼동을 방지하고자 한다면 `state.cityDetail` 처럼 원본 상태 객체에 명시적으로 접근하는 것이 더 직관적일 수 있습니다.

## 17. 비동기 렌더링과 이벤트 바인딩 시점 에러 (addEventListener of null)
**Q: `Cannot read properties of null (reading 'addEventListener')` 에러가 왜 발생했나요?**
**A:** 
자바스크립트의 실행 컨텍스트와 DOM 조작의 **라이프사이클(Lifecycle)** 불일치로 인한 에러입니다. `render` 함수를 선언만 하고 호출하지 않은 상태에서 (즉, 가상 HTML 문자열이 실제 DOM 트리에 주입되기도 전에) `querySelector`로 DOM 노드를 탐색하려 했기 때문에 `null`이 반환된 것입니다. DOM 요소에 이벤트를 바인딩하려면 반드시 **HTML 요소가 실제 DOM 트리에 주입(`render()` 호출 완료)된 직후**에 수행해야 합니다.

## 18. API 응답 래퍼(Wrapper) 처리 (Cannot read properties of undefined)
**Q: 상세 페이지에서 `Cannot read properties of undefined (reading 'cost')` 에러가 났습니다.**
**A:** 
클라이언트 컴포넌트의 데이터 모델과 서버의 API 응답 스펙 간의 불일치 문제입니다. 프론트엔드 컴포넌트는 평탄화된 단일 객체 `{ city: "...", info: { ... } }`를 기대했으나, 실제 API 서버는 `cityDetail`이라는 상위 키로 한 뎁스 더 감싼 래퍼(Wrapper) 객체 `{ cityDetail: { city: "...", info: { ... } } }` 형태로 응답했습니다. 이를 해결하기 위해 데이터 ㅍㅔ칭 모듈(`api.js`)에서 `return data.cityDetail`로 응답 데이터를 정제하여 컴포넌트로 전달함으로써 구조적 결합도를 낮췄습니다.
