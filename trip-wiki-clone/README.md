# ✈️ Trip Wiki Clone (Vanilla JS SPA)

이 프로젝트는 React나 Vue 같은 프론트엔드 프레임워크를 **전혀 사용하지 않고 오직 순수 바닐라 자바스크립트(Vanilla JS)만으로** 밑바닥부터 만들어낸 SPA(Single Page Application)입니다. 

브라우저의 기본 기능과 자바스크립트의 비동기 통신을 활용하여 현대적인 웹 어플리케이션이 화면을 전환하고 데이터를 관리하는 근본적인 원리를 학습하기 위해 제작되었습니다.

---

## 🛠️ 기술 스택
- **Core**: HTML5, Vanilla JavaScript (ES6+), Vanilla CSS
- **Build Tool**: Vite
- **API**: Trip Wiki 서버 API 통신 (Fetch API)

---

## 🚀 개발 절차 및 상세 설명

이 프로젝트는 총 4개의 페이즈(Phase)로 나누어 점진적으로 기능을 확장하며 완성되었습니다.

### Phase 1: 프로젝트 세팅 및 SPA 라우팅 뼈대 만들기
프레임워크 없이 페이지 새로고침 없는 부드러운 화면 전환(SPA)을 구현하는 기초 공사 단계입니다.

1. **Vite 바닐라 템플릿 생성**: `npx create-vite@latest` 명령어를 통해 가장 가벼운 바닐라 개발 환경을 구축했습니다.
2. **진입점(`index.html` & `index.js`) 세팅**: 모든 자바스크립트 코드가 그려질 빈 도화지 `<div id="app"></div>`를 만들고, `src/index.js`와 `src/App.js`를 연결했습니다.
3. **마법의 주문(`history.pushState`) 도입**: 링크를 클릭했을 때 브라우저가 깜박거리며 새로고침 되는 것을 막고, 주소창의 텍스트만 싹 바꾸는 기술을 적용했습니다.
4. **뒤로 가기 센서(`popstate`) 장착**: 사용자가 브라우저의 뒤로 가기/앞으로 가기 버튼을 눌렀을 때 이를 감지하여 화면을 다시 그려주는(`render`) 이벤트를 달았습니다.

### Phase 2: 외부 데이터 통신 (API) 및 컴포넌트 구조화
백엔드 서버와 소통하고, 화면을 부품(Component) 단위로 쪼개어 관리하는 단계입니다.

1. **통신병(`api.js`) 생성**: 서버에 데이터를 요청하는 비동기 함수(`fetch`, `async/await`)를 만들고, 지역/정렬/검색어에 따라 쿼리스트링(`?start=0&region=Asia...`)을 조합하여 요청하는 로직을 구현했습니다.
2. **부서(Component) 나누기**: 화면을 헤더(`Header`), 지역 탭(`RegionList`), 도시 목록(`CityList`) 3개의 독립적인 함수로 쪼개어 코드의 재사용성과 가독성을 높였습니다.

### Phase 3: 메인 페이지 렌더링 및 이벤트 연동
중앙 관리실(`App.js`)을 중심으로 상태(State)를 관리하고 사용자 행동에 반응하는 단계입니다.

1. **중앙 창고(`state`) 도입**: `App.js`에 `state` 객체를 만들어 현재 주소, 지역, 검색어, 데이터 목록 등을 중앙에서 한 번에 통제하도록 설계했습니다.
2. **정렬 및 검색 기능 연동**: 헤더에서 검색어나 정렬을 바꾸면 통신병(`api.js`)에게 새 명령을 내리고, 받아온 새 데이터로 `state.cities`를 갈아 끼운 뒤 화면을 다시 그리게(`render`) 했습니다.
3. **이벤트 리스너 메모리 누수(좀비 버그) 해결**: 
   - 기존의 파괴적인 `$app.innerHTML +=` 대신 기존 요소를 보존하는 `$app.insertAdjacentHTML`을 도입했습니다.
   - 컴포넌트가 다시 렌더링될 때마다 클릭 센서가 2배, 4배로 증식하는 치명적 버그를 막기 위해, 최상단 윈도우가 아닌 **새로 생성되는 하위 DOM**(`id="regionNav"`, `id="cityGrid"`)에만 센서를 달아 렌더링 시 기존 센서가 깔끔히 삭제되도록(Garbage Collected) 최적화했습니다.

### Phase 4: 상세 페이지(CityDetail) 기능 완성 및 고도화
특정 데이터를 클릭했을 때 상세 페이지로 전환하고 데이터를 렌더링하는 최종 단계입니다.

1. **상세 API 요청 추가**: `api.js`에 특정 도시의 ID로 단일 데이터를 가져오는 `requestCityDetail` 함수를 추가했습니다. (이때 서버가 데이터를 포장해 둔 `data.cityDetail` 알맹이만 벗겨오는 실무 팁을 적용했습니다.)
2. **상세 페이지(`CityDetail.js`) 렌더링**: 메인 화면에서 특정 사진을 클릭하면, 주소를 `/city/{id}`로 변경하고 `CityDetail` 부서를 호출하여 큰 이미지와 상세 점수를 화면에 출력했습니다.
3. **뒤로 가기 상태 복원 완벽 대응**: 상세 페이지에서 뒤로 가기를 눌렀을 때, 다시 서버를 부르지 않고 기존 창고에 있던 `state.cities`를 꺼내어 순식간에 이전 화면 상태를 완벽 복원했습니다.
