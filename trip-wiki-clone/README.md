# ✈️ Trip Wiki Clone (Vanilla JS SPA)

이 프로젝트는 React나 Vue 같은 프론트엔드 프레임워크를 **전혀 사용하지 않고 오직 순수 바닐라 자바스크립트(Vanilla JS)만으로** 밑바닥부터 만들어낸 SPA(Single Page Application)입니다. 

브라우저의 기본 API와 자바스크립트의 비동기 통신을 활용하여 현대적인 웹 어플리케이션이 화면을 전환하고 상태(State)를 관리하는 근본적인 아키텍처를 학습하기 위해 제작되었습니다.

---

## 🛠️ 기술 스택
- **Core**: HTML5, Vanilla JavaScript (ES6+), Vanilla CSS
- **Build Tool**: Vite
- **API**: Trip Wiki 서버 API 비동기 통신 (Fetch API)

---

## 🚀 개발 절차 및 아키텍처 상세

이 프로젝트는 총 4개의 페이즈(Phase)로 나누어 점진적으로 기능을 확장하며 완성되었습니다.

### Phase 1: 프로젝트 세팅 및 SPA 클라이언트 라우팅 뼈대 구축
프레임워크 없이 브라우저의 새로고침을 방지하고 부드러운 화면 전환(SPA)을 구현하는 라우팅 기초 공사 단계입니다.

1. **Vite 바닐라 템플릿 생성**: `npx create-vite@latest` 명령어를 통해 경량화된 바닐라 개발 환경을 구축했습니다.
2. **엔트리 포인트(`index.html` & `index.js`) 세팅**: 모든 컴포넌트 렌더링의 타겟이 될 루트 컨테이너 `<div id="app"></div>`를 정의하고 메인 앱(`src/App.js`)을 연결했습니다.
3. **History API (`history.pushState`) 도입**: 네비게이션 클릭 시 브라우저의 기본 동작(페이지 리로드)을 차단하고 URL 경로만 변경하는 클라이언트 사이드 라우팅을 적용했습니다.
4. **팝스테이트 이벤트(`popstate`) 바인딩**: 사용자가 브라우저의 뒤로 가기/앞으로 가기 버튼을 눌렀을 때 이를 감지하여 라우트 경로를 갱신하고 화면을 다시 렌더링(re-render)하도록 이벤트를 연동했습니다.

### Phase 2: 외부 데이터 통신 (API) 모듈화 및 컴포넌트 분리
백엔드 서버와 데이터를 주고받는 로직을 모듈화하고, 화면을 독립적인 컴포넌트로 분리하는 단계입니다.

1. **API 통신 모듈(`api.js`) 생성**: 서버에 데이터를 비동기 요청(`fetch`, `async/await`)하는 전용 헬퍼 함수를 작성하고, 지역/정렬/검색어 등의 조건에 따라 쿼리스트링 파라미터(`?start=0&region=Asia...`)를 동적으로 조합하는 로직을 구현했습니다.
2. **UI 컴포넌트 분할**: 전체 UI를 헤더(`Header`), 지역 네비게이션(`RegionList`), 도시 목록(`CityList`) 등 독립적인 함수형 컴포넌트로 분리하여 코드의 응집도를 높이고 의존성을 낮췄습니다.

### Phase 3: 전역 상태(State) 관리 및 이벤트 위임 최적화
최상위 컴포넌트(`App.js`)를 중심으로 상태를 중앙 집중식으로 관리하고 사용자 인터랙션을 처리하는 단계입니다.

1. **중앙 상태 객체(`state`) 도입**: `App.js`에 `state` 객체를 정의하여 현재 라우트 경로, 선택된 지역, 검색어, 응답 데이터 리스트 등을 단일 진실 공급원(Single Source of Truth)으로 통제하도록 설계했습니다.
2. **정렬 및 검색 기능 통합**: 헤더 컴포넌트에서 검색어나 정렬 기준이 변경되면 API 비동기 함수를 재호출하고, 응답받은 새 데이터로 `state.cities`를 갱신한 뒤 UI 렌더링 사이클을 재실행하도록 데이터 플로우를 구성했습니다.
3. **이벤트 리스너 메모리 누수 방지 및 DOM 렌더링 최적화**: 
   - 렌더링 시 기존 DOM 트리를 완전히 파괴하는 `$app.innerHTML +=` 대신, 돔 노드를 보존하면서 삽입하는 `$app.insertAdjacentHTML`을 도입했습니다.
   - 컴포넌트 재호출(리렌더링) 시마다 상위 요소에 전역 이벤트 리스너가 중복 누적되는 메모리 누수(Memory Leak) 현상을 방지하기 위해, **새롭게 렌더링되는 하위 노드**(`id="regionNav"`, `id="cityGrid"`)에만 이벤트를 위임(Event Delegation)했습니다. 이를 통해 리렌더링 시 이전 DOM과 바인딩된 리스너가 안전하게 가비지 컬렉션(GC) 되도록 최적화했습니다.

### Phase 4: 동적 라우팅 및 상세 페이지(CityDetail) 구현
특정 엔티티 선택 시 상세 페이지 라우트로 전환하고 데이터를 렌더링하는 최종 단계입니다.

1. **단일 리소스 조회 API 추가**: `api.js`에 특정 도시의 식별자(ID)를 이용해 단일 상세 데이터를 패칭하는 `requestCityDetail` 함수를 추가했습니다. (이때 서버 응답 래퍼 구조인 `data.cityDetail`을 언래핑(Unwrapping)하여 컴포넌트 결합도를 낮추는 실무 패턴을 적용했습니다.)
2. **상세 페이지(`CityDetail.js`) 렌더링**: 메인 화면에서 특정 아이템을 클릭하면 URL을 동적 경로(`/city/{id}`)로 변경하고, 메인 컴포넌트들을 숨긴 뒤 `CityDetail` 컴포넌트를 마운트하여 상세 정보를 렌더링했습니다.
3. **라우팅 히스토리 상태 복원**: 상세 페이지에서 뒤로 가기(popstate) 발생 시, 불필요한 네트워크 재요청 없이 기존에 캐싱해둔 `state.cities` 데이터를 즉시 렌더링하여 무중단 상태 복원을 완벽하게 구현했습니다.
