## 💡 핵심 Q&A (학습 노트)

실습을 진행하며 다루었던 핵심 질문과 개념들을 정리했습니다.

### Q1. 화면을 그릴 때 `innerHTML` 말고 다른 방법은 없나요?
물론 있습니다! 정석적인 방법으로는 `document.createElement()`와 `appendChild()`를 사용하여 DOM 요소를 하나하나 생성해 붙이는 방식이 있습니다. 
하지만 이 방식은 코드가 너무 길어지고 복잡해집니다. 반면 `innerHTML`을 사용하면 HTML 구조를 문자열 형태로 한눈에 볼 수 있어서 **Vue의 템플릿(<template>) 문법과 가장 비슷한 선언적인 형태**를 띱니다. 
(참고: 실제 Vue나 React는 `innerHTML`을 통째로 쓰지 않고, 내부적으로 '가상 돔(Virtual DOM)'을 활용해 변경된 부분만 `createElement` 방식으로 효율적으로 업데이트합니다.)

### Q2. 컴포넌트(함수) 이름은 왜 대문자로 시작하나요? (`CityItem`)
자바스크립트의 일반적인 함수는 소문자(`camelCase`)로 시작하는 것이 관례입니다. 하지만 컴포넌트나 클래스 역할을 하는 함수는 **대문자로 시작(`PascalCase`)**하는 것이 전 세계적인 약속입니다.
1. 개발자가 코드를 읽을 때 **"이 함수는 화면 UI를 만들어내는 특별한 컴포넌트구나!"** 라고 한눈에 알아볼 수 있습니다.
2. Vue나 React 같은 프레임워크에서는 컴포넌트를 HTML 태그처럼 사용합니다 (`<CityItem />`). 이때 첫 글자가 대문자여야 기존에 존재하는 기본 HTML 태그(`<div>`, `<li>`)의 오타로 착각하지 않고 커스텀 컴포넌트로 인식합니다.

### Q3. 일반 함수에 `new` 키워드를 붙여서 호출할 수도 있나요?
네, 정확합니다! ES6(2015년)에 `class` 문법이 도입되기 전까지, 자바스크립트는 일반 함수에 `new`를 붙여서 객체를 생성해 내는 **'생성자 함수(Constructor Function)'** 방식으로 객체 지향 프로그래밍을 했습니다.
현재 이 프로젝트는 `new`나 `this`를 전혀 사용하지 않는 **최신 함수형 트렌드(클로저 활용)** 방식으로 작성되었습니다.

### Q4. '클로저(Closure)'란 무엇이고, 이 코드에 어떻게 적용되었나요?
단순히 변수가 있다고 클로저가 생기는 것은 아닙니다. 
1. 텐트(함수) 안에 수첩(`state`)이 있고, 
2. 그 수첩을 사용하는 로봇(내부 함수, 이벤트 리스너)이 있으며,
3. 그 로봇이 텐트 밖(버튼의 클릭 이벤트)과 연결되어 계속 살아남게 될 때 형성됩니다.

함수(`CityList`)의 실행이 끝났음에도 불구하고, 화면에 있는 '추가하기'나 '좋아요' 버튼을 누르면 안쪽의 `state`가 지워지지 않고 값을 유지한 채 업데이트됩니다. 이렇게 변수를 안전하게 살려두는 마법의 가방 같은 역할을 하는 것이 클로저입니다.

### Q5. 덧셈을 할 때 `5.69999999999997` 같은 숫자가 왜 나오나요?
자바스크립트를 포함한 컴퓨터 언어가 소수를 0과 1(이진수)로 표현하면서 발생하는 **'부동 소수점 오차'** 때문입니다.
이를 해결하기 위해 `.toFixed(1)`을 사용하여 소수점 첫째 자리까지 잘라냅니다. 이때 반환값이 문자열이 되므로, 숫자 연산을 위해 변수 앞에 **단항 연산자 `+`**를 붙여주어 `+(score).toFixed(1)` 형태로 숫자로 다시 변환하는 것이 실무에서 자주 쓰이는 세련된 팁입니다.

### Q6. 이벤트 리스너 안의 `render()`와 맨 밑의 `render()`, 화면이 두 번 연속으로 그려지나요?
아닙니다! 맨 아래에 작성한 `render()`는 프로그램이 켜질 때 최초로 화면을 그리기 위해 **딱 한 번** 즉시 실행됩니다.
반면 `addEventListener` 안에 들어있는 `render()`는 나중에 사용자가 버튼을 눌렀을 때만 발동하도록 세팅해 둔 '알람 시계'와 같습니다. 따라서 클릭이나 폼 제출이 발생할 때만 추가로 실행됩니다.
